# changelog/

发布正文默认由提交信息自动生成（`scripts/changelog.mjs`）。
如果某个版本需要补充背景、迁移说明、截图链接，就在这个目录放一个同名文件，
**发版时以手写文件为准**，自动生成的内容只用来起模板。

## 用法

```bash
# 1. 按当前提交生成模板（内容即自动生成结果）
pnpm changelog -- --init 2.0.2

# 2. 编辑 changelog/2.0.2.md，随便改：加小节、删掉不重要的条目、写说明

# 3. 发版。CI 会把 changelog/2.0.2.md 原样作为 Release 正文
pnpm release:patch
```

- 文件名 = 版本号去掉开头的 `v`：`v2.0.2` → `2.0.2.md`
- 没有手写文件时，自动生成的正文已经够用，不必每次都建
- 手写文件是**覆盖**关系，不是追加：想保留自动内容，就基于 `--init` 的模板改
- 写完记得提交，CI 是从仓库里读的
